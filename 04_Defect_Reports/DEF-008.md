## Steps to reproduce

1. Open the home page.
2. Enter name *Rahul Verma*, phone `12345`, guests 3.
3. Click **Reserve table**.

**Test data:** name Rahul Verma, phone 12345, guests 3

## Expected result

Error message shown **and** the form keeps Rahul Verma / 12345 / 3 so the user only fixes the phone.

## Actual result

Error shown but name and phone are empty, guests reset to 2 and date reset to tomorrow – user must retype everything.

## Evidence

Screenshot `07_Screenshots/selenium/cycle1_TC-UI-04_form_after_error.png`; Cycle 1 log: TC-UI-04 *Actual: Name '', phone '', guests '2'*.

## Root cause

In `web.book()` the error branch re-rendered the template with `_form_defaults()` instead of the submitted form values.

## Fix

Re-render with `{**_form_defaults(), **request.form.to_dict()}`.  
File: `application/reservation_system/web.py` · Fixed in build **v1.1.0** · Commit `b7aa2ec`

## Retest (Cycle 2)

Re-ran TC-UI-04 on build v1.1.0 – **all passed**. Full regression (127 test cases + 31 Postman assertions) also passed, so the fix did not break anything else. Status changed to **Closed**.
