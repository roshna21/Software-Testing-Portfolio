# DEF-003: Double booking: a booking that starts earlier and runs into an existing one is accepted

| Field | Value |
|---|---|
| Defect ID | DEF-003 |
| Status | **Open** |
| Severity | Critical |
| Priority | P1 |
| Module | M2 Table allocation |
| Requirement | R7 |
| Found in build | v1.0.0 (Cycle 1) |
| Detected by | TC-BVA-30, TC-BVA-31, PM-08 |
| Environment | Python 3 / Flask, Chrome headless, test clock Mon 16 Nov 2026 10:00 |
| Reported by | Roshna Sai |

## Steps to reproduce

1. Book a party of 7 for Wed 18 Nov at **19:00** (gets T8, busy 19:00–20:30).
2. Book another party of 7 for the same day at **18:30** (would hold T8 18:30–20:00).

**Test data:** Existing: party 7 @ 19:00 (T8). New: party 7 @ 18:00 / 18:30

## Expected result

Second booking rejected – *No table available* (T8 is the only table for 7 and the times overlap).

## Actual result

Second booking **accepted on table T8** – two groups are given the same table at the same time.

## Evidence

Cycle 1 log: TC-BVA-30 *Actual: Accepted (R1002, table T8, deposit Rs.700)*; Newman PM-08 got 201 instead of 409.
