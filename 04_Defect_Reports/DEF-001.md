# DEF-001: Party of 8 guests is rejected although 8 is allowed

| Field | Value |
|---|---|

| Reported by | Roshna Sai |

## Steps to reproduce

1. Open the booking form (or `POST /api/reservations`).
2. Enter valid details with **Guests = 8**.
3. Submit.

**Test data:** party_size = 8, date 2026-11-18, 13:00

## Expected result

Booking accepted and table T8 assigned (8 is the upper limit of the valid range 1–8).

## Actual result

Rejected with *"Party size must be between 1 and 8"* – the message itself says 8 is allowed.

## Evidence

Cycle 1 log: TC-BVA-05 *Actual: Rejected: Party size must be between 1 and 8*; Newman PM-06 got 400 instead of 201.

## Root cause

`validate_party_size()` used `MIN_PARTY <= size < MAX_PARTY` – a strict `<` at the upper boundary (classic off-by-one).

## Fix

Changed the comparison to `<=`.  
File: `application/reservation_system/validators.py` · Fixed in build **v1.1.0** · Commit `acdd0ea`

## Retest (Cycle 2)

Re-ran TC-BVA-05, PM-06 on build v1.1.0 – **all passed**. Full regression (127 test cases + 31 Postman assertions) also passed, so the fix did not break anything else. Status changed to **Closed**.
