## Steps to reproduce

1. Book a table with phone `98765432101` (11 digits).
2. Submit.

**Test data:** phone = 98765432101 and 987654321012

## Expected result

Rejected – phone must be exactly 10 digits.

## Actual result

Booking accepted and stored with the 11/12-digit number.

## Evidence

Cycle 1 log: TC-BVA-16 *Actual: Accepted (R1001, table T1)*.

## Root cause

The regex `[6-9]\d{9}` was used with `re.match`, which only anchors the **start** of the string; extra digits at the end were ignored.

## Fix

Use `re.fullmatch(r"[6-9]\d{9}", phone)` so the whole value must match.
